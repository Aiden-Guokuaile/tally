# 「文件架」页

> 把文件拖到刘海上，面板展开到文件架并暂存一份副本；从这里拖出去、AirDrop、打开，到了保留时间自动清理（拖进来的文件默认 1 天，自动收进来的截图默认 30 分钟，设置里调）。按住 ⌘ 拖出去是「剪切」：访达把**来源文件本身**搬到目标，架上那份副本随后清掉。交互形态照 NotchDrop（MIT），代码是重写的，理由在下面。

## 拖放

拖放目标挂在面板根视图上（`NotchView` 的 `.onDrop(of: [.fileURL])`），闭合和展开都接：

- 闭合态文件拖到刘海上（`isTargeted` 变真）→ `NotchState.dropEntered` → 控制器切到文件架页并展开（不钉住，拖走了照常按光标位置收起）。
- 展开态拖到任何一页上 → 切到文件架页；落下后 `ShelfDrop.handle` 从 item provider 里取 `public.file-url`，交给 `ShelfStore.add(urls:)`。
- 开关关了 `.onDrop` 的类型列表为空，等于不注册拖放目标。

**拖进来永远是复制**，来源文件原地不动：架上这份是副本，到了保留时间就清掉，它要是唯一一份就会丢文件。要剪切在拖出去那一步做。

## 从命令行放进来

`open -a Tally <文件…>`（脚本、agent 跑完把产物丢过来）：`AppDelegate.application(_:open:)` 收到文件 URL 交给 `NotchController.receiveFiles`，和拖进来一样复制一份进文件架，闭合态弹一条「放进文件架」（[panel.md](panel.md)「提示」）。Tally 没在跑时这条命令会把它拉起来，文件比 `didFinishLaunching` 先到、控制器还没建，就先攒着，建好再放。文件架关着不偷偷打开开关，只弹「文件架没开」。`Info.plist` 不声明文档类型：访达「打开方式」里没有 Tally，只有明说 `-a Tally` 才进来。

## 截图自动放进来（`ScreenshotWatcher`）

设置「文件架 → 新截图自动放进文件架」（默认关，文件架关着时点不了）：截图一落进截图文件夹就复制一份到文件架，走和上面同一条路（弹「放进文件架」）——截完直接从刘海拖进 Claude Code / Codex。

- **文件夹要用户点过**：打开开关时弹选择面板，默认指到系统截图位置（`com.apple.screencapture` 的 `location`，没设过是桌面），点「用这个文件夹」才开。桌面、文稿、下载受隐私保护，用户在选择面板里点选这一下，系统把授权记在那个目录上（`com.apple.macl`），跨重启都能读、不弹框、不用安全书签。取消就不开。不知道截图工具存在哪、或者存在选择面板点不进去的地方（Lens 存在 `/var/folders` 下的 `$TMPDIR/Lens`）时，有两条路，都不认具体是哪个截图软件：

- **截一张图找文件夹**（`ScreenshotFolderFinder`）：点了之后 30 秒内用 FSEvents（文件级事件）盯家目录和 `$TMPDIR` 的上一层，第一个「新建或改名进来的图片文件」所在的文件夹就是结果；隐藏目录（废纸篓、各种 `.cache`）、`/Library/Caches/`（浏览器一直在写缩略图）、Tally 自己的数据目录排除。找到了显示路径和那张图的文件名，点「用这个」才套用——那 30 秒里别的程序也可能写图片；30 秒没动静就说这个工具可能只放剪贴板、不存文件。
- **粘贴路径**：输入框点「使用」（去掉空白和引号、展开 ~，得是存在的文件夹，不是就红字说）。

这类目录不受隐私保护，不用点选授权。不做「检测到某某截图软件就给个按钮」：换个软件、改个保存位置就不管用了。读不了（授权没了、目录没了）时原因亮在设置里，不默默失效。
- **系统截图位置认标记，工具的文件夹认图片**：选的是系统截图位置（桌面，别的文件也往那儿放）时，新文件带扩展属性 `com.apple.metadata:kMDItemIsScreenCapture` = true 才算（系统截图和 CleanShot 都写，复制后还在；直接 `getxattr` 读，不等 Spotlight 建索引；文件名随系统语言和用户设置变，不看）。选的是别的文件夹（Lens、Shottr 这类截图工具自己的保存目录）时，新出现的图片（`UTType` 属于 image）都算：这些工具多数不写标记——Lens 存在 `$TMPDIR/Lens` 的图实测一个标记都没有，只认标记的话一张都收不到。
- **系统截图快捷键全关时提示**：`com.apple.symbolichotkeys` 里 28 / 29 / 30 / 31 / 184 五个全是 `enabled = 0`（偏好里没写的键默认开着），说明截图走的是别的工具，系统截图位置不会再有新截图；这时选的又是系统位置，设置里橙字提示去选那个工具的保存文件夹。原来什么都不说，开关开着却一张都收不到。
- **只收新的**：开始盯的那一刻把已有文件的 inode 记成见过；之后在访达里改名还是同一个 inode，不重复放。截图的缩略图还浮在角上时文件在临时目录，消失后才挪进文件夹，所以一挪进来就是完整文件，不用等大小稳定。
- 目录用 `DispatchSource`（`O_EVTONLY` + `.write`）盯，一次截图会连着触发几次，攒 0.5 秒再扫一遍比对。盯的是文件描述符不是路径：目录被删、被挪走（iCloud 桌面同步、外接盘拔掉）之后再也不来事件，所以 `.delete` / `.rename` 也收，收到就停下、设置里亮出原因；开始时或扫的时候读不了（授权被收回）同样亮出来。停下之后每 30 秒再试一次，文件夹回来就自动接着盯：截图工具放在临时目录里的文件夹会被系统清掉、下次存图又建回来，不重试的话就一直停着，只剩设置里一行没人看的红字。关掉功能、换文件夹时撤掉重试。开关、文件夹、文件架开关变了才重起（`start` 同一文件夹幂等，不然每次改设置都会把这段时间到的截图记成见过）。

## 拖出去与剪切（`ShelfDragSource`）

拖出去默认是复制：目标目录多一份，架上和来源都还在。**按住 ⌘ 拖出去**（访达的老约定）是移走。右键「移动到…」是同一件事的确定性版本——弹系统的选目录面板，不依赖修饰键和访达的判断。选目录面板和移动失败的提示框都包在 `NotchPanel.steppingAside` 里，否则被面板盖住（见 [panel.md](panel.md)）。

**交出去的 URL 是来源文件本身，不是架上那份副本**（`ShelfStore.cutURL`）。交副本的话，「剪切」就成了「把暂存那一刻的快照搬到目标，再把来源删掉」：盘上凭空多一次整文件的复制（11 MB 也好 2 GB 也好），目标拿到的还是旧内容，来源那份还得想办法处置（第一版是丢进废纸篓，于是一次剪切在盘上留下两份 11 MB 的东西）。交来源就是访达自己做一次改名：同卷瞬时、内容是当前的，架上那份副本直接删掉即可。来源已经不在原处（自己动过、或者本来就是从 Safari 拖来的临时文件）才退回交架上那份。

拖源不能用 SwiftUI 的 `.onDrag`：它只交出一个 `NSItemProvider`，拿不到拖放结束时目标执行的到底是 copy 还是 move，删早了会丢文件。所以改成 AppKit 的拖放会话——`ShelfDragSource` 是个空的 `NSView`（`.background` 里，`hitTest` 返回 nil，不吃点击、不挡 hover 和右键），SwiftUI 那边用 `DragGesture(minimumDistance: 4)` 起会话：

- `draggingSession(_:sourceOperationMaskFor:)` 交 `[.copy, .move]`，按不按 ⌘ 由访达定。只给 `.move` 的话不按 ⌘ 也会搬走。
- `draggingSession(_:endedAt:operation:)` 拿结果：`.move` 走 `ShelfStore.remove`（文件已经被访达搬走了，这里只清架上那份副本和索引），`.copy` 和 `[]`（拖到没人接的地方）什么都不做。
- 起会话要一个鼠标事件，用 `NSApp.currentEvent`；拿不到就记一行日志并放弃，不硬来。

## 存储（`ShelfStore`）

目录 `~/Library/Application Support/Tally/shelf/`：`index.json`（每件的 id、名字、大小、加入时刻、来源路径——剪切要靠它找回来源文件，老索引缺这个键解出来是 nil，原子写）、`files/<id>/<原文件名>`（副本，各自一个目录所以同名不冲突）、`thumbs/<id>.png`（QuickLook 缩略图 96pt @2x，生成不了的用文件图标）。复制在后台线程；`add` 是 async，界面用 `Task` 调。

内存只有索引里的几个字段；缩略图只在这页可见时（`start()`）读进内存，收起或切页（`stop()`）就放掉；开关关掉（`setEnabled(false)`）索引也放掉，磁盘上的东西不动，再开还在。

**保留多久**：每件记着种类（`ShelfItem.kind`）：「新截图自动放进文件架」收进来的是 `screenshot`，拖进来的、`open -a Tally` 放进来的是 `file`，老索引里没有这个键的按 `file` 算。两种各有保留时长（设置「文件架 → 保留多久」，数值 + 分钟 / 小时 / 天，存分钟，夹在 1 分钟到 30 天；文件默认 1 天，截图默认 30 分钟——截图一天几十张，留久了把文件架塞满）。**到点就清**：定时器排到最早那一件的过期时刻（多等 1 秒），清完、增删、改时长都重排。定时器挂在默认运行循环模式：拖文件、弹选择面板期间不触发，结束后补上——挂到 `.common` 的话，正往外拖的那件可能被当场删掉；开关打开、这页可见、改设置时也各清一次。原来只在打开这页时清，过了时间的副本可能在磁盘上多躺好几天。`expired` / `nextExpiry` 是纯函数。

和 NotchDrop 的差别：它把缩略图当 PNG `Data` 常驻内存并 base64 进 JSON、启动即解码全部条目、常驻全局鼠标监视器和 1 Hz 定时器；这里没有任何常驻监听，关掉零内存。

## 页

页标题摘要「N 项 · 文件留 1 天 · 截图留 30 分钟」（跟着设置走，空的时候是提示语），卡片顶行是操作提示+ 右侧「AirDrop 全部」「清空」；下面自适应网格，每件缩略图 44pt + 名字（中间截断）+ 大小。点开（`NSWorkspace.open`），按住拖出去是文件本身（⌘ 是剪切，见上），悬停右上角出删除叉，右键：打开 / AirDrop / 移动到… / 在访达中显示 / 删除。AirDrop 走 `NSSharingService(named: .sendViaAirDrop)`，面板不抢激活，调之前先 `NSApp.activate` 系统面板才出得来。空态是 160pt 高的虚线框「拖文件到这里」，有东西时网格也至少 160pt：拖放靶子给足，页也不至于矮得像残页。

设置窗口「文件架」一节：开关、存放位置（在访达中显示）、已暂存几项、清空。

## 验证

```bash
swift test --filter 'ShelfStoreTests|ScreenshotWatcherTests|ScreenshotFolderFinderTests|PreferencesTests'
./scripts/install.sh --build && sleep 3; pkill -x Tally; while pgrep -x Tally >/dev/null; do sleep 0.5; done
open -a Tally --args --open shelf && sleep 5 && screencapture -R256,0,1000,480 -x /tmp/tally-shelf.png
```

用例：加两份同名文件各自成项且副本存在、重开实例索引还在、删除连文件一起删、清空；没开不收、可见时缩略图在内存、不可见放掉、关掉索引清空但磁盘保留；过期判定（截图和文件各按各的时长、老索引没标种类的按文件算、定时器排到最早那一件、到点清掉不等打开这页、时长文案能整除用大单位）；`cutURL` 来源还在时交来源、来源没了退回架上那份；老索引缺 `source` 能解出来；「移动到…」搬的是来源、架上那份跟着清掉、废纸篓里不多东西，目标已有同名文件时报错且什么都不动；截图（系统位置带标记才算、名字像截图不算、工具的文件夹里新图片都算而不是图片的不算、系统截图快捷键五个全关才提示且没写进偏好的算开着、找文件夹只认新建或改名进来的图片文件且排除隐藏目录、缓存和 Tally 自己的目录、粘贴的路径去空白引号且得是存在的文件夹、隐藏文件不列、开始盯之前就在的不算、改名不重复放、读不了的文件夹把原因亮出来、盯着的目录被删掉后停下并说原因、文件夹回来后自动接着盯；找文件夹真跑一次 FSEvents 能找到临时目录里新建的图）。截图：空态虚线框；手动：从访达拖一个文件到刘海上 → 面板展开到文件架并出现该项；把它拖回桌面得到一份副本，来源还在；**按住 ⌘ 拖回桌面 → 桌面有、架上那件消失、来源原处没有了且废纸篓里也没有**（它是被改名过去的）；右键 AirDrop 出系统面板；`open -a Tally /tmp/x.txt` → 闭合态弹「放进文件架 x.txt」、文件架里多一项；退出 Tally 后再跑一次同样的命令 → Tally 被拉起来且这一项照样进来。
